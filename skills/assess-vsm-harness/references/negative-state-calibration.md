# Negative-state calibration — bounded absence and unresolved evidence

**Methodology version:** 0.3.7

**Status:** adjudication examples / calibration guide; not a new VSM definition, classification symbol, or assessment field. Profile 0.2.4 and existing Methodology thresholds remain authoritative.

## Procedure

1. Pin upstream source revision and declare the system-in-focus, recursion, supported standard-distribution modes, credited first-party surfaces, and explicitly excluded adjacent surfaces.
2. **Test positive ownership before negatives.** For each function map the disturbance, decisive organizational right, owner, and return/closure. Check supported optional modes and, for S3/S4/S5, legitimate parent-governed paths before concluding absence.
3. Trace **plausible first-party paths checked** that could materially close the function in the declared shipped mode. Use primary code wiring, supported configuration, actual runtime entry points, tests, and operating documentation. A component label is not a function witness.
4. Choose `—` only with a defensible **bounded** no-material-first-party-path conclusion and the existing `Absence scope`: (a) surfaces inspected, (b) plausible first-party paths checked, (c) why no material path remains. Exhausting *every imaginable extension* or proving impossibility is not required.
5. Choose `?` when reviewed primary evidence is insufficient for **both** a positive result and that bounded negative conclusion—for example, a specific plausible *shipped* path is unresolved, the supported mode cannot be examined, or material boundary coverage is incomplete. State the actual unresolved question in the existing Evidence gaps section where identifiable.
6. Never substitute historical corpus frequency for source evidence. **The absence of a positive witness alone does not establish `—`**: the negative conclusion still requires the existing boundary-relative `Absence scope`. Likewise, a hypothetical future plugin or feature alone does not require `?`.

A retired, ignored, test-only, dogfood-only, or third-party mechanism does not establish a positive path at the stated boundary. Before concluding `—`, examine whether there is a separate *active shipped* path; if that specific path cannot be resolved, `?` may be justified. Ordinary permission or configuration control alone does not establish S5, just as routine QA does not automatically establish S3*.

## Reviewer questions

- For `?`: what **concrete supported** plausible path or coverage gap prevents a defensible `—`? If none is identified, re-examine whether the written no-material-path conclusion is already supported.
- For `—`: are all three absence-scope elements substantive and tied to the *declared standard-distribution boundary*? If not, inspect further or retain `?`.
- For both: did the reviewer test the positive and parent-governed alternatives first, distinguish supporting enforcement from decision ownership, and avoid borrowing adjacent/external actors?

## Compatibility and correction

No field, state definition, positive threshold, burden of negative evidence, synthesis/ranking operation, or mandatory new artifact section changes. Methodology 0.3.7 does **not** trigger a bulk migration or auto-replace `?` with `—`. Reassessments (including suspected Index batch #1314 drift) require separate source evidence, existing Index review/admission/checkpoint gates, and preserved immutable `generated_*` provenance.
